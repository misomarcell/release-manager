# Redesign brief

This is the hand-off for adopting the approved redesign of Release Manager. It was worked out with the owner over three review rounds. Read it together with:

- `.impeccable/mocks/redesign/index.html` — the visual reference. Open it in a browser; the Dark/Light switch at the top re-themes every frame. It is a static mockup built from throwaway markup, not Angular code. Copy its values and structure, not its code.
- `PRODUCT.md` — product truth, including the plans this design prepares for.
- `DESIGN.md` — describes the **old** interface. It is the "before", kept for reference. Rewrite it (and `.impeccable/design.json`) from the finished build, not before.

All titles, posters, plots and release names in the mockup are invented placeholders. "Tracker 2" is a placeholder tracker name.

## What the owner asked for

- Stay close to Material 3, but look modern and stop reading as stock Angular Material.
- One consistent design across the whole app. Inconsistency between pages was the main complaint.
- Easy to use while still showing plenty of information.
- Dark and light themes, following the device setting.
- English only. Nothing in the interface is Hungarian.
- The title details page and its actions deserve the most care.

## Decisions that are settled

### Color

Theme roles only; no hard-coded hexes in components. Green-tinted neutrals with a teal primary.

These values were hand-tuned in the mockup. They are close to a Material 3 teal scheme but were not generated by `mat.theme`; expect to define a custom palette or override system tokens to hit them.

### Typography

- **Google Sans Flex** for all interface text. **Google Sans Code** only for release names and file paths. Both are on Google Fonts. The owner chose this pairing after comparing six.
- Weights in the mockup: 650 page and detail titles, 600 row titles, 500–550 buttons and labels, 450–500 chips and tags, 400 body.
- Sizes: detail title 30px desktop / 23px phone, page title 26px, row title 16px, section heading 16px, body 14–14.5px, meta 13px, tags 11.5px, release names 12.5px mono.
- Chips and tags must not look heavy. This was explicit feedback.

### Shape

- Lists are segmented groups: items sit 2px apart, inner corners 6px, the outer corners of the group 18–20px. A selected item rounds fully (20px).
- The same language is reused by the status cells, the action bar, release lists, key/value lists and sheets.
- Posters 10px (rows), 14–16px (detail, tiles). Buttons are pills (40px, 34px small). Filter chips 8px. Tags 6px. Detail pane and sheets 28px.
- No shadows on content. Tone separates surfaces.

### Shell and navigation

- **Phone:** bottom navigation bar with four destinations: Releases, Library, Watchlist, Discover. The watchlist unread count is an amber badge on its icon.
- **Desktop (from 960px):** a navigation rail with the same four items. Every item's icon sits on the same 56×48 rounded rectangle (14px radius); the active one fills with the secondary container color.
- The drawer is removed. Manage Users, Administration, Logs and Sign out move behind the account avatar (top bar on phone, bottom of the rail on desktop). These admin pages are **not designed yet**.
- **Top bar is always 56px tall at the same offset**, whether it holds a search field, a back button with title, or a page title.
- "Recommendations" is renamed **Discover** in navigation, because the long word does not fit a four-item bottom bar.

### List pages

- One row pattern everywhere: poster, title, one meta line, one line of tags and state chips, and a trailing column whose content depends on the page (top seeder count and release count on Releases, size on disk on Library, new/known count on Watchlist, a Follow button in title search).
- Filters are visible chips under the search bar, not a hidden menu. Library's first chip is "All", not "Both".
- Rows show resolutions on offer (2160p, 1080p) and state chips ("In library", "Following").
- Opening a title is a full page on the phone and a side pane on desktop (list–detail). Rows no longer expand in place.
- URL query params for search, filters and page stay as they are (see `AGENTS.md`).

### Title details page

One layout for every context, top to bottom:

1. **Header:** poster, title, a facts line (type, year, runtime, rating, star score), genres. On desktop the plot sits beside the poster.
2. **Plot** under its own "Plot" heading, in the same style as other section headings. It must never float without a label.
3. **Action bar:** equal segmented cells, icon above label, both centred. Left group: Follow (becomes Following), Trailer, IMDb, and More on desktop. A gap, then a separate right-hand group: Like, Dislike. Active states fill with the primary container. More holds the remaining menu items (Is It Woke?, Open in Jellyfin where it is not the primary button, Delete item).
4. **At most one filled button per page**, only where there is a real primary action: Open in Jellyfin (Library), Mark as read (Watchlist), Search releases (Discover). Releases has none; the per-release download buttons are the action.
5. **Status:** three cells — Trackers, Library, Watchlist — saying where the title stands. Three columns on desktop, three full-width rows on the phone so nothing truncates.
6. **Context content:** the release list (Releases), seasons and media info (Library), new releases and the keyword filter (Watchlist), the AI reason (Discover).

### Releases and trackers

- The design must not assume nCore is the only source. Say "trackers". Each release names its tracker: a Tracker column on desktop, a label in the stats line on the phone. The Releases search bar carries a tracker picker ("All trackers").
- A release shows parsed tags first, then the raw name in mono, wrapping at the dots.
- Freeleech is a compact **FL** badge next to the tracker name. It is not written out, and it never sits among the quality tags.
- Seeders are green with an up arrow, leechers red with a down arrow, in tabular figures.
- **Never label a release "best".** There is no ruleset for that. The Trackers status cell lists what exists ("5 releases · on 2 trackers · 2160p, 1080p, 720p") without ranking.

### Search

- Releases searches releases ("Search releases…"). Library searches the library ("Search library…"). Both stay.
- **New: search all titles.** Discover's top bar is "Search all titles…" and looks titles up through TMDB, so a title can be followed before any release exists. Result rows show library and following state and a Follow button. The Watchlist page has a plus button that opens the same search.

### Sheets

Download ("Send to qBittorrent") and the watchlist add/edit dialog are bottom sheets on phones. In the download sheet the save path is the focused field. In the watchlist sheet Remove is kept apart from Save.

## What this needs beyond styling

These are not in the app today. Check before building the UI around them.

| Design element | Needs |
| --- | --- |
| Quality tags on rows and releases | The release parser exposing resolution, source and HDR tags. Not verified. |
| Tracker name per release, tracker picker | A tracker field on release models. Only nCore exists, so the picker has one entry until more are added. |
| "on N trackers" in the status cell | Same as above. |
| Search all titles | A backend TMDB search endpoint and a results view. |
| "Search releases" from a Library title | A shortcut that exists today only on release cards and recommendations. |
| Light theme | The app is dark only today (`color-scheme: dark` in `styles.scss`). |
| Like/Dislike on every title page | Present today inside media details; confirm it is available in all four contexts. |

Small copy additions in the mockup that the owner has seen but not singled out: the hint under the save path, and the explanation under the watchlist release filter.

## Not done

- Login, Manage Users, Administration and Logs are not designed.
- Loading, empty and error states are not drawn. Keep the existing skeleton approach, restyled to the new shapes.
- The desktop title-search layout is not drawn; use the same list–detail layout as the other pages.
- The mockup was checked in a browser in dark theme at desktop and phone widths. The light theme was checked once, before the last two rounds of changes.
- `index.html` still declares `lang="hu"`; it should be `en`.

## Suggested order of work

1. Theme: palette, typeface, shape tokens, light and dark.
2. Shell: bottom bar, rail, 56px top bar, account menu.
3. The shared title row and list container, then the shared title details view.
4. Pages in order: Releases, Library, Watchlist, Discover.
5. Sheets for download and watchlist.
6. New capabilities: all-titles search, tracker field.
7. Rewrite `DESIGN.md` and `.impeccable/design.json` from the finished build, and remove the mockup-only ignores in `.impeccable/config.json` if the mockup is deleted.

Run `pnpm validate` at the end, as `AGENTS.md` requires.
